# BUDOWA GROUP — TEST: базовий аудит 21.11.2026

> **Статус:** чинний контрольний аудит для подальшої розробки. Режим: TEST, без змін оригінальних Google Sheets і резервних копій.  
> **Перевірка:** вихідний Flutter-код і `backend/Code.gs` у GitHub, GitHub Actions, метадані та вибіркові формули двох TEST-таблиць; фактичні екрани планшета з листування. **Реальні CREATE/UPDATE в Google Sheets не підтверджені.**

Цей файл є постійним контрольним списком проєкту. Наступні результати доповнюють аудит; невиконані пункти не вважаються готовими без перевірки. Робоча процедура: [WORKFLOW.md](WORKFLOW.md). Оперативний стан: [STATUS.md](STATUS.md).

## 1. Основні висновки

- Є працююча основа Android-застосунку Flutter з Google Sign-In, TEST API і переглядом дев'яти вкладок двох TEST Google Sheets.
- UI має оформлення BUDOWA GROUP: заставку, фонові зображення, кольорові картки та фінансову панель.
- Є форми додавання й редагування та тестова серверна реалізація запису, **але в робочому Apps Script на планшеті було підтверджено v0.4 (лише читання)**. Підготовлений код v0.5 у репозиторії сам по собі не розгортається.
- Жодної перевіреної реальної операції CREATE/UPDATE із застосунку в TEST-таблиці немає. Не заявляти протилежне.
- Дані оригінальних Google Sheets і їхні резервні копії не змінювати, навіть якщо виникає збій у TEST.

## 2. Перевірка дев'яти вкладок

| Книга | Вкладка | Перегляд | Додавання/редагування |
|---|---|---|---|
| Облік робочих годин | Робочі години | Згруповано за датою, новіші першими; картки за об'єктами | Форми є, реальний запис не підтверджено |
| Облік робочих годин | Розрахунок | Групи за місяцями, усі працівники місяця | Лише читання формул |
| Облік робочих годин | Працівники | Посада, ставка, статус | Частково: ставка розрахункова, перейменування заборонене |
| Облік робочих годин | Обʼєкти | Адреса, статус, кольори | Частково: ідентифікатор об'єкта не перейменовується |
| Облік робочих годин | Історія ставок | Новіша дата початку першою | Форми підготовлено, E2E не проведено |
| Фінанси та закупівлі | Операції | Дата за спаданням, тип, сума, категорія | Форми підготовлено, E2E не проведено |
| Фінанси та закупівлі | Панель | Надходження, витрати, баланс, З/П, об'єкти | Лише читання формул |
| Фінанси та закупівлі | Закупівельники | Надходження, витрати, баланс | Частково: тільки ім'я, баланси — формули |
| Фінанси та закупівлі | Довідники | Окремо категорії й об'єкти | Додавання підготовлено, редагування у списку неповне |

**Кольори об'єктів:** наявна логіка `siteColor()` у Flutter жорстко визначає п'ять відомих об'єктів, а не отримує колір динамічно з джерела. Кольори в усіх розділах мають бути однаковими й відповідати Google Sheets, включно з новими об'єктами.

**Сортування:** Робочі години — найновіша дата першою, усі записи кожної дати; фінансові операції та історія ставок — новіші спочатку; Розрахунок — найновіший місяць, усі працівники, далі попередній місяць та всі працівники; активні довідники — відповідно до правил джерела. Сортування не має змінювати фізичний номер рядка, використаний для редагування.

## 3. Вибіркова звірка даних на дату аудиту

У фінансовій TEST `Панель`: надходження **154 947,33 zł**, витрати **169 854,49 zł**, баланс **−14 907,16 zł**, З/П працівникам **68 051,50 zł**. Арифметика балансу збігається. У відповідних перевірених комірках не було попередньої `#REF!`.

Ці значення — **історичний знімок перевірки**, не поточні вічні підсумки. Майбутні звіти мають читати дані наново.

## 4. Блокувальні проблеми (P0)

1. **Некоректний `expected` у Android**: у `lib/main.dart` ключі початкового стану для серверної перевірки були `'undefined'` замість цифрових індексів колонок; тому редагування має ризик `EDIT_CONFLICT_REFRESH`. Виправлення, тестування: [#1](https://github.com/budowagroup/BUDOWA-GROUP-Android/issues/1).
2. **Історія дій не закрита для адміністратора**: `action=history` у підготовленому `backend/Code.gs` не перевіряв роль `owner`. Правило: **історію дій бачить тільки власник**. Захист і регресійні тести: [#2](https://github.com/budowagroup/BUDOWA-GROUP-Android/issues/2).
3. **Apps Script v0.5 не розгорнуто**: створити копію v0.4, перенести чинні дозволи адміністраторів у захищені Script Properties, спочатку розгорнути v0.5 з `ENABLE_TEST_WRITES=false`; перевірити всі вкладки, власника і 2+ адміністративні доступи відповідно до фактичного старого списку: [#3](https://github.com/budowagroup/BUDOWA-GROUP-Android/issues/3).
4. **Реальні тести CREATE/UPDATE не пройдені**: лише після read-only перевірок дозволяти власнику запис у TEST; перевірити створення, зміну, ідемпотентність, формули, суми, журнал, відкат і відсутність змін оригіналів: [#4](https://github.com/budowagroup/BUDOWA-GROUP-Android/issues/4).

**Доки P0 не підтверджені, встановлювати `ENABLE_TEST_WRITES=true` заборонено.**

- **[#7](https://github.com/budowagroup/BUDOWA-GROUP-Android/issues/7):** повнота завантаження; зараз читання завершується після порожньої порції 30 рядків, хоча записи можуть бути далі. Перевірити великі таблиці, сортування, коректну адресацію.
- **[#8](https://github.com/budowagroup/BUDOWA-GROUP-Android/issues/8):** однакові кольори об'єктів за Google Sheets у всіх розділах; динамічне додавання нових об'єктів.

## 6. Реліз та UX (P2)

**[#9](https://github.com/budowagroup/BUDOWA-GROUP-Android/issues/9):** пошук і фільтри, дати/суми в zł, адаптивність телефон/планшет, owner-only журнал в інтерфейсі, відновлення після мережевих збоїв, релізне підписання APK/AAB, тестування прав, продуктивності та повний контрольний огляд.

## 7. Що підтверджено та чого не підтверджено

- Google-вхід власника та читання TEST: підтверджені скриншотами планшета.
- Компіляція Android: успішна GitHub Actions [#45](https://github.com/budowagroup/BUDOWA-GROUP-Android/actions/runs/44806766190).
- Backend тести: успішні [поточні автоматичні тести](https://github.com/budowagroup/BUDOWA-GROUP-Android/actions/runs/44814944636) на момент аудиту. Це **симуляції**, не запис у справжні Google Sheets.
- Реальне додавання/редагування, рольова безпека після розгортання, production/release: **не підтверджені**.
- Старі `README.md` і `docs/STATUS.md` до цього аудиту описували v0.2 та вимагали актуалізації.

## 8. Постійні правила роботи

1. Оригінальні Google Sheets, їхні формули, дані, кольори та автоматичні резервні копії — **недоторканні без окремого прямого дозволу**; тільки TEST-розробка.
2. Один пріоритет — одна логічна зміна — перевірка — звіт. Не починати P1/P2, доки блокери P0 не вирішені.
3. Для кожного коміту — GitHub Actions; для backend — automated tests; для змін запису — реальні E2E TEST-дані, звірка формул і журналу.
4. Не видавати успішну компіляцію або мок-тести за підтверджену роботу функції.
5. Не змінювати діючий Apps Script та не вмикати запис автоматично; після підготовки — окремий перевірений staged rollout.
6. У відповідях позначати: **Зроблено**, **У роботі**, **Заблоковано**, **Не почато**; додавати конкретні посилання на коміти/збірки/Issues та результат перевірки.
7. Після кожного прийнятого етапу оновлювати `docs/STATUS.md` і закривати Issue лише за критеріями приймання.

## 9. Черговість робіт

**P0:** #1 → #2 → #3 (спершу лише читання) → #4 (справжній TEST-запис).  
**P1:** #5 → #6 → #7 → #8 (порядок P1 уточнювати лише за залежностями; без ризику для P0).  
**P2:** #9 (перед релізом).

**Поточний gate:** реальний запис вимкнений, оновлення Apps Script і E2E-тестування заблоковані до виправлення #1 та #2 і безпечного staged rollout.
