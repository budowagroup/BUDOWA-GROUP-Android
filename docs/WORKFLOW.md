# Робочий процес BUDOWA GROUP — TEST

> Джерело вимог: [Аудит 21.11.2026](AUDIT_2026-11-21.md). Головне правило: **ніяких записів в оригінальні таблиці**. Робоча мова звітів — українська.

## Джерела правди

1. `docs/AUDIT_2026-11-21.md` — базовий повний аудит і незмінні обмеження.
2. GitHub Issues [#1–#9](https://github.com/budowagroup/BUDOWA-GROUP-Android/issues) — поточний backlog і приймальні критерії.
3. `docs/STATUS.md` — що фактично виконано, перевірено, заблоковано і над чим працюємо.
4. CI GitHub Actions — підтвердження компіляції й модульних/мок-тестів, **не** доказ успішного реального запису.
5. TEST Google Sheets та планшет — джерела фактів для реальної перевірки.

## Короткий цикл виконання (одна задача за раз)

1. **Вибрати:** найважливіший відкритий P0 Issue; P1/P2 не брати замість відкритого P0-блокера.
2. **Перевірити джерело:** прочитати актуальний репозиторій, TEST-аркуші та вимоги; оригінали — тільки на читання для порівняння, якщо потрібно.
3. **Змінити:** мінімальний обсяг коду з прив'язкою до Issue; без зміни оригіналів, backup-автоматизацій і реального розгортання Apps Script без контрольних перевірок.
4. **Перевірити:** синтаксис, unit tests, Flutter analyze, CI; за потреби TEST-інтеграційні сценарії.
5. **Задокументувати:** підсумок коміту, посилання на CI, що змінилося, які перевірки фактично пройдені та що залишилося; оновити `docs/STATUS.md`.
6. **Закрити Issue тільки при виконаних checkbox і доказах**; інакше залишити відкритим. Повторити цикл.

## Gate A — Код безпечний

- [ ] Flutter компілюється, analyzer без error.
- [ ] На сервері тестується owner/admin/unknown і owner-only history.
- [ ] `expected` містить коректні індекси колонок, редагування не підміняє чужий рядок.
- [ ] Немає записів у оригінали, токенів, персональних даних у комітах чи логах.
- [ ] Нові фічі не зачіпають формули й довідники без контролю залежностей.

## Gate B — Розгортання API на читання

- [ ] Збережена повна відкатна копія робочого Apps Script v0.4.
- [ ] Перенесені дійсні адмін-дозволи (`READ_ONLY_ADMINS`) без публікації їхнього списку.
- [ ] У Script Properties: `ENABLE_TEST_WRITES=false`; збережений поточний OAuth client ID.
- [ ] Відредагований чинний deployment, не створений дубль, збережений `/exec` або синхронізований GitHub secret.
- [ ] Owner та адміністратори читають дозволені вкладки, сторонні не мають доступу; історія тільки owner.
- [ ] Усі дев'ять вкладок працюють. Якщо ні — негайний відкат.

## Gate C — Обмежене TEST-редагування

- [ ] Gates A і B пройдені.
- [ ] Власник окремо увімкнув `ENABLE_TEST_WRITES=true`.
- [ ] CREATE/UPDATE TEST фінансів та годин доведені реальними тестами на TEST-копіях.
- [ ] Підтверджені формули, підсумки, відсутність дубля, журнал, права, помилки й відкат.
- [ ] Оригінальні та backup-таблиці після тестів незмінні.

**Аварійне зупинення:** Script Properties → `ENABLE_TEST_WRITES=false`. Якщо пошкоджена доступність читання — відкат до збереженої v0.4.

## Gate D — Перед релізом

- [ ] Усі дев'ять екранів прийняті на планшеті та телефоні.
- [ ] Динамічні місяці/кольори, повнота великих таблиць, пошук/фільтри, коректні локалізовані числа.
- [ ] Готова власницька історія, повторна авторизація, зрозумілі помилки, перевірена продуктивність.
- [ ] Усі P0/P1 необхідні для випуску Issues закриті, P2 release checklist пройдено.
- [ ] Підписана релізна збірка та реальна перевірка; debug APK не вважати релізом.

## Формат кожного звіту

**Наступний пріоритет:** посилання на Issue.  
**Зроблено:** конкретний коміт/файл/функція.  
**Перевірено:** успішна CI / unit / TEST-перевірка з посиланням.  
**Заблоковано:** зовнішня дія користувача, відсутній доступ або тест, що не пройдено.  
**Залишилося:** одна наступна дія за послідовністю аудиту.

Ніколи не казати «готово» про зміни, які існують лише в GitHub, але не розгорнуті на сервері або не протестовані на пристрої.
