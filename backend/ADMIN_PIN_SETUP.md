# BUDOWA GROUP Android TEST — персональні паролі двох адміністраторів

**Стан:** код підготовлено в GitHub, але робочий Apps Script v0.5 **ще не оновлено** до v0.6. Сама зміна GitHub не встановлює паролі на сервері. Це додатковий пароль **для Android-застосунку**, а не пароль Google.

## Що буде після активації

- Власник `biuro.budowa.group@gmail.com` входить через Google.
- Два акаунти з `READ_ONLY_ADMINS` входять через Google **і** персональний пароль.
- Сервер перевіряє PIN і видає тимчасову сесію на 30 хвилин. Адміністратори не можуть записувати дані незалежно від `ENABLE_TEST_WRITES`.
- Після 5 невдалих спроб — блокування наступних спроб на 15 хвилин.
- PIN не зберігається в APK, GitHub, логах або URL. Під час першого налаштування він тимчасово вноситься в Script Properties і потім автоматично стирається, залишається HMAC-SHA256 з серверним секретним ключем.

## Порядок дій для власника (без створення нової копії)

1. Відкрий **основний**, не резервний, Apps Script:
   https://script.google.com/home/projects/1JUkBuI1qdx0k4EleMGGCmiYqDK2TDnkaSxwlqrRIgX6kiuyZroAwXRj3/edit
2. У редакторі заміни **весь** вміст існуючого `Код.gs` вмістом `backend/Code.gs` v0.6:
   https://github.com/budowagroup/BUDOWA-GROUP-Android/blob/main/backend/Code.gs
3. У лівій панелі **Файли → + → Скрипт** створи другий файл `AdminPin.gs` та встав у нього **повністю**:
   https://github.com/budowagroup/BUDOWA-GROUP-Android/blob/main/backend/AdminPin.gs
   Не створюй другого `doPost` і не копіюй пароль у код.
4. **Налаштування проєкту → Властивості скрипта → Редагувати**:
   - `READ_ONLY_ADMINS` — два реальні підтверджені email через кому, у такому порядку: спочатку Роман, потім Ярослав.
   - `GOOGLE_OAUTH_CLIENT_ID` — існуючий Web OAuth (не змінювати).
   - `ENABLE_TEST_WRITES` — `false` (**не змінювати**).
   - **Тимчасово** створи `ADMIN_PIN_SETUP_1` із паролем адміністратора №1, який власник уже вибрав.
   - **Тимчасово** створи `ADMIN_PIN_SETUP_2` із паролем адміністратора №2, який власник уже вибрав.
   - Збережи властивості. У GitHub, чат, файли коду й скриншоти значення паролів **не переносити**.
5. У редакторі обери функцію `bgInitializeAdminPins` у списку функцій та натисни **Запустити** під Google-акаунтом власника. Функція перевіряє рівно два акаунти, створює секретний `ADMIN_PIN_PEPPER`, зберігає лише `ADMIN_PIN_HASH_...` і видаляє `ADMIN_PIN_SETUP_1` та `ADMIN_PIN_SETUP_2`. Якщо з'явиться вікно дозволів, уважно перевір назву скрипта, перш ніж підтверджувати.
6. Повернись у **Властивості скрипта**: перевір, що **обидва `ADMIN_PIN_SETUP_*` відсутні**, є `ADMIN_PIN_PEPPER` та **рівно два** ключі `ADMIN_PIN_HASH_...`; `ENABLE_TEST_WRITES=false`. Скриншот — тільки із прихованими значеннями.
7. **Ввести в дію → Керувати введеннями в дію → чинне BUDOWA GROUP Android API → Редагувати (олівець) → Нова версія**, опис: `BUDOWA GROUP Android API v0.6 — TEST admin passwords / READ ONLY`. Натисни **Ввести в дію**. НЕ створюй `Нове розгортання`; поточний `/exec` має залишитися незмінним.
8. На Android встанови **лише успішно зібрану** APK **v0.3.3+8** із GitHub Actions, підписану тим самим ключем. Перевір вхід власника, роль `owner` і 9/9 TEST-вкладок; далі окремо перевір обох адміністраторів із власними Google-акаунтами й паролями.
9. Перевір негативні випадки: без пароля, з неправильним паролем, під чужим Google-акаунтом та без сесії — дані не повинні відкриватися; обидва адміни залишаються лише читачами.

**Відкат:** у тому самому вікні `Керувати введеннями в дію → Редагувати → Версія` можна вибрати стару версію v0.5, якщо вона досі доступна. Для адміністраторів стара версія **не вимагатиме** додаткового пароля. Змінювати оригінальні бухгалтерські таблиці, автоматизації резервного копіювання та TEST-ідентифікатори не можна.

**Безпека:** вибрані у чаті короткі паролі придатні лише для обмеженого TEST. Перед робочим запуском заміни їх сильними унікальними паролями; Google MFA залишається обов'язковим додатковим захистом.
